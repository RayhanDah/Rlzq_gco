# Sprint Phase 4a — run court de validation (planifié le 2026-11-13)

Objectif (`docs/PLAN.md`, Phase 4a) : attaquer le risque R1 (amorçage de l'exploration en GCO) avant tout gros calcul.
Run court de ≈ 0,3 à 1B steps, 3 seeds, GCO-S **et** GCO-std. Critère de sortie : **S1 atteint sur au moins 1 seed en
GCO-std**, sinon arrêt et diagnostic (kill criteria). Livrable exigé par le gate G3 : `docs/reports/run_4a.md`.

Point de départ : Phase 3 terminée, smoke test PASS (`docs/reports/smoke_test.md`, commit ea0e7de).

## Ce qui manque aujourd'hui pour lancer 4a
- **Aucune évaluation** : `src/eval` n'existe pas. S1 se mesure par des matchs (spec §4), pas par la récompense
  d'entraînement, qui vaut ≈ 0 en self-play par construction (`docs/01_papers.md` §1.9).
- **Pas de pool d'adversaires** : la boucle fait du self-play contre la version courante seulement. La spec §3 prévoit
  « self-play + passé » pour GCO-S comme pour GCO-std, et s'entraîner contre le seul plus récent est le pire choix
  rapporté (`docs/01_papers.md` §1.8).
- **Gardes incomplètes** : S1 n'est jamais détecté, pas de checkpoint à l'itération 0 (revue T6).
- **Débit soutenu et RAM de la vraie boucle non mesurés** : le smoke test dure 19 s.

## Points d'attention
- GCO strict : aucun mécanisme d'exploration appris dans ce sprint. GCO-std ne diffère de GCO-S que par les états
  initiaux génériques. Les priorités R&D (spec §8) se testent une par une **après** ce run, selon son résultat.
- Kill criterion du plan : aucun but contre l'adversaire gelé après 1B steps sur 3 seeds en GCO-std ⇒ arrêt,
  diagnostic, une seule intervention à la fois.
- Hors sprint : bot RLBot complet, délai d'action d'un tick (ablation), reprise bit à bit sur XPU.
